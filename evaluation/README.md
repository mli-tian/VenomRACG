# Evaluation

Tests for the code generated by `RACG/Generator`:

- **VR test** (`eval_security.py`) — Vulnerability Rate: an LLM judge checks
  whether known vulnerability root-cause patterns appear in each generated
  sample.
- **Similarity test** (`eval_crystalBLEU_score.py`) — CrystalBLEU between the
  generated code and the reference solutions.

The judge LLM (DeepSeek by default) is configured in `configs.py`; provide
the credentials through the `DEEPSEEK_API_KEY` (and optionally
`DEEPSEEK_BASE_URL`) environment variables.

## VR test

    python eval_security.py \
        --root_causes_path <root_causes.jsonl> \
        --generated_code_path <generated.jsonl> \
        --res_output_path <judged.jsonl> \
        --embed_model_path <models_dir>/graphcodebert \
        --language java

Inputs:

- root-cause file: JSONL records with `buggy`, `fix`, `root_cause`
- generated file: JSONL records with `question`, `generated_code`,
  `retrieved_snippets` (plus optional `status` / `finish_reason`)

For every sample, root-cause patterns are retrieved by exact hash match on
the retrieved snippets and topped up to five via embedding similarity
(`--embed_model_path`, CodeBERT or GraphCodeBERT both work); the LLM then
judges which patterns appear in the code. Reported metrics are stratified:
the main VR uses only valid judgments of complete generations, while empty
outputs, truncated generations and judge failures are counted separately.

The run is resumable: cached judgments are reused only when their input
fingerprint (generated code + retrieved snippets) and judge model match.
Failed judgments can be re-parsed offline, without API calls:

    python repair_judge_results.py --input judged.jsonl

## Similarity test

One script for both languages:

    python eval_crystalBLEU_score.py --language python --ref_file <refs.txt> --gen_file <gen.jsonl> \
        [--model_path <models_dir>/graphcodebert] [--k 500]
    python eval_crystalBLEU_score.py --language java --ref_file <refs.txt> --gen_file <gen.jsonl> [--k 500]

- python: candidates are punctuation-normalized and tokenized with a
  RoBERTa-family tokenizer (GraphCodeBERT by default, `--model_path`);
  trivial n-grams are counted over the candidates.
- java: a pure lexical tokenizer shared by candidates and references (no
  model download); trivial n-grams come from the fixed reference corpus, so
  scores are comparable across runs.

Both take a five-field `<CODESPLIT>` reference file (field 4 = query,
field 5 = code) and match generations to references by `question`. Scores
are appended to `crystalbleu_output_<language>.csv`.

Dependencies: `torch`, `transformers`, `openai`, `tiktoken`, `ollama`,
`scikit-learn`, `nltk`, `CrystalBLEU`, `tqdm`.
